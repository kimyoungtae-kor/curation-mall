# MVP 개발 로드맵

## 1. 목표와 기준

- 시작일: 2026-08-12
- 시연일: 2026-08-29
- 목표: 사업자에게 링크로 시연할 수 있는 반려동물용품 쇼핑몰 MVP
- 제품 형태: 모바일 우선 반응형 웹. 향후 앱 전환을 고려해 프론트엔드와 API를 분리한다.
- 기술 기준안: Next.js + TypeScript, Java Spring Boot, PostgreSQL
- 개발 원칙: 로컬 개발을 우선하되, 배포 가능성은 마지막 날까지 미루지 않는다.
- 완료 정의: 홈에서 상품을 발견하고, 상세·찜·장바구니를 거쳐 회원 또는 비회원으로 테스트 주문을 완료할 수 있으며, 관리자가 상품과 주문을 확인할 수 있다.

## 2. 범위

### 반드시 시연할 핵심 흐름

1. 홈의 히어로/상품 슬라이드와 상황·테마별 기획전

3. 회원가입, 로그인, 로그아웃

6. 테스트 결제 또는 결제 시뮬레이션과 주문 완료

8. 관리자 로그인, 이미지 파일 업로드와 안전한 삭제를 포함한 상품 관리, 주문 조회·상태 변경

10. 외부에서 접근 가능한 HTTPS 시연 링크

예정 일정보다 먼저 로컬 구현한 항목은 다음과 같다.

- 홈 7개 섹션, 공개 기획전, 5초 히어로 교차 전환
- 상품 24개·옵션 26개, 검색·필터·상세·품절 예시
- 회원가입·로그인·로그아웃·현재 사용자, 방문자 식별
- 회원 전용 DB 찜, 회원·비회원 장바구니, 수량 변경·삭제, 로그인 시 장바구니 병합
- 회원·비회원 견적·주문, 서버 가격 재계산, 20분 재고 예약
- 테스트 결제 승인·실패·중복 요청, 예약 만료와 재고 복원
- 회원 주문 내역, 비회원 주문번호+조회 토큰 조회
- 관리자 상품·옵션·재고·상태와 조건부 삭제, 이미지 파일 업로드, 주문 조회·상태 전이, 홈 섹션·히어로, 회원 목록 API
- 동일 장바구니 행 동시 주문 차단, 비회원 조회 토큰 멱등 재생, 만료 결제 반복 409, 관리자 옵션 낙관락과 홈 JSON 스키마 검증 보강
- 백엔드 PostgreSQL Testcontainers 56개와 프론트 Vitest 16개 파일·51개, typecheck·lint·production build 통과

아직 게이트를 통과한 것으로 보지 않는 항목은 새 이미지 업로드 코드의 stage 반영·재시작 영속성·외부 백업, 운영 환경 Flyway·백업·복구, 모바일 실기기 E2E와 5분 시연 2회다. 관리자 이미지 업로드는 수동 `storageKey` 입력을 대체하도록 범위에 편입하고, 기획전 CRUD·분류 CRUD·회원 상세는 Later로 관리한다.

## 2.2 2026-08-15 배포 순서 가속

로컬 핵심 기능이 계획보다 먼저 준비돼 배포 스파이크를 8월 15일부터 시작한다. 단일 EC2 `t3a.medium` stage Compose를 먼저 공개하고 외부 수동 QA를 받은 뒤, 결함 수정·테스트 문서화·Playwright 자동화를 순서대로 진행한다. Prometheus·Grafana·k6는 기능·배포 안정화 뒤 자원 여유가 있을 때 추가한다.

## 4. 핵심 게이트

### G1 — 8/14 요구사항 동결

- 화면·API·DB의 1차 범위를 고정한다.
- 새 기능 요청은 기존 항목과 일정·위험도를 비교해 하나를 빼고 하나를 넣는 방식으로만 반영한다.
- 디자인 완성도보다 구매 흐름과 데이터 무결성을 우선한다.

### G2 — 8/18 배포 가능성 검증

- 최종 운영 배포가 아니라도 외부 HTTPS 링크에서 프론트 → Spring Boot → PostgreSQL 흐름을 확인한다.
- 기존 서버를 사용할 때는 소유자 승인과 충돌 여부 확인 후에만 변경한다.
- 기존 서버가 부적합하면 8/18에 대체 배포안을 확정한다. 이후 기능 개발과 배포 조사를 동시에 끌고 가지 않는다.

### G3 — 8/23 고객 구매 흐름 완료

- 회원과 비회원 각각 한 번씩 주문 완료까지 통과한다.
- 결제금액은 서버가 다시 계산한다.
- 주문번호와 조회 수단이 동작하며, 주문·결제 결과가 DB에 남는다.

### G4 — 8/26 기능 동결

- 신규 기능을 중단하고 버그 수정, 콘텐츠 입력, 반응형 보정, 시연 안정화만 수행한다.
- 미완성 부가기능은 숨기거나 제거한다. 비활성 버튼을 남기지 않는다.

### G5 — 8/28 출시 후보 승인

- 데모 계정, 비회원 조회 정보, 데이터 백업, 환경변수, HTTPS, CORS, 권한을 확인한다.
- 5분 데모 시나리오를 최소 2회 연속 성공해야 한다.

## 5. 일정이 밀릴 때 범위 절감 우선순위

아래 순서대로 뒤에서부터 제거한다. 핵심 구매 흐름과 데이터 안전성은 제거하지 않는다.

1. 애니메이션, 전환 효과, 장식성 인터랙션 축소
2. 홈 슬라이드 수와 기획전 수 축소
3. 관리자 홈 구성 편집을 고정 슬롯 편집으로 제한
4. 필터·정렬·검색 고도화 제거
5. 찜은 회원 전용으로 유지하고, 기존 고객 로그인 전에 담은 장바구니 상품은 병합해 유지
6. 결제사를 붙이지 못하면 명확히 표시된 테스트 결제 시뮬레이션으로 대체
7. 이미지 업로드를 다중 이미지에서 대표 이미지 중심으로 축소
8. 관리자 대시보드 통계 제거

다음 항목은 일정 절감을 위해 제거하지 않는다.

- 회원가입·로그인과 관리자 권한 분리
- 기존 고객 로그인 시 장바구니 유지, 신규 가입은 빈 회원 데이터로 시작
- 회원·비회원 주문
- 서버 가격 재계산과 주문 스냅샷
- 상품·재고·주문 데이터의 DB 저장
- 주문 조회와 관리자 주문 확인
- 기본 오류 처리와 HTTPS 시연 링크

## 6. 매일 작업 종료 규칙

- 변경된 요구사항과 결정은 `docs/DECISIONS.md`에 기록한다.
- 완료한 작업, 미완료 작업, 다음 작업, 막힌 점을 해당 문서 또는 진행 기록에 갱신한다.
- DB 변경은 Flyway 마이그레이션으로 남기고 수동 변경에 의존하지 않는다.
- 시연을 깨뜨릴 수 있는 변경은 작은 단위로 검증한다.
- 비밀키·비밀번호·서버 접속 정보는 문서나 Git에 기록하지 않는다.

## 7. 5분 시연 시나리오

1. 모바일 크기로 홈에 접속해 상황별 기획전을 연다.
2. 상품 상세에서 이미지와 옵션을 확인하고 찜·장바구니에 담는다.
3. 비회원으로 주문하고 주문번호로 조회한다.
4. 회원으로 로그인해 주문 내역 또는 찜을 확인한다.
5. 관리자에서 같은 주문을 확인하고 상태를 변경한다.
6. 관리자에서 상품이나 노출 정보를 수정한 뒤 고객 화면에 반영되는 것을 보여준다.
