# 데모 상품·콘텐츠 데이터 준비 계획

기준일: 2026-08-12  
상태: 방식 확정, 실제 데이터 생성 전

## 1. 결론

초기 MVP 데이터는 다른 쇼핑몰에서 복사하거나 크롤링하지 않는다. 다음 세 가지 출처를 순서대로 사용한다.

1. 상품명, 설명, 가격, 옵션, 재고는 프로젝트용 **가상 상품 데이터**로 직접 만든다.
2. 상품·기획전 이미지는 프로젝트 분위기에 맞는 **자체 생성 이미지**를 사용한다.
3. 중국 바이어·국내 위탁업체가 사용을 허용한 실제 상품 자료를 받으면 가상 데이터를 교체한다.

따라서 공급처 자료가 아직 없어도 개발과 시연 준비를 시작할 수 있다. 실제 운영 상품으로 교체할 때도 상품 API와 DB 구조는 바꾸지 않는다.

## 3. 상품 한 개에 필요한 필드

사업자가 나중에 CSV 또는 관리자 화면으로 바꿀 수 있도록 다음 값을 준비한다.

| 구분 | 필드 예시 |
|---|---|
| 식별 | 내부 상품코드, SKU, 슬러그 |
| 분류 | 브랜드, 동물 종, 카테고리, 연결 기획전 |
| 표시 | 상품명, 한 줄 설명, 상세 설명, 검색 키워드 |
| 가격 | 정상가, 판매가, 배송 정책 |
| 옵션 | 색상·크기·용량, 옵션별 SKU·추가금·재고 |
| 상태 | 임시저장, 공개, 숨김, 판매종료, 품절 |
| 이미지 | 대표 이미지 키, 상세 이미지 키, 대체 텍스트 |
| 정렬 | 신상품·인기상품 여부, 기획전·홈 노출 순서 |

가상 상품 설명에는 치료, 질병 예방, 전문가 보증처럼 확인되지 않은 효능을 넣지 않는다.

## 4. 이미지 준비 방식

### 개발 초반

- 로컬 기본 이미지를 사용해 이미지가 없어도 레이아웃과 오류 처리가 동작하게 한다.
- 상품마다 먼저 대표 이미지 한 장만 연결한다.
- 외부 이미지 URL에 의존하지 않아 인터넷 상태 때문에 시연이 깨지지 않게 한다.

### 데모 품질 보강

- 상품 카드: 정사각형 1:1, 권장 1200×1200
- 기획전: 4:3 또는 16:10
- 히어로: 데스크톱과 모바일에서 안전하게 잘리는 구도
- 흰 배경 제품 사진만 반복하지 않고 일부는 집 안 공간에 배치된 라이프스타일 장면으로 구성
- 파일은 WebP 중심으로 최적화하고 원본과 웹용 결과물을 분리
- 모든 의미 있는 이미지에 한국어 대체 텍스트 작성

레퍼런스 사이트의 상품 사진, 배너, 로고, 카피를 내려받아 사용하지 않는다. 공급처 이미지는 사용 범위가 확인된 것만 저장하며 출처·허용 범위를 내부 메모로 남긴다.

## 5. DB 입력 방식

가상 상품을 관리자 화면에서 24번 수동 입력하지 않는다.

```text
편집용 CSV/JSON
  → 필수 필드·가격·SKU·재고 검증
  → local/stage 전용 seed 작업
  → PostgreSQL
  → Spring API
  → Next.js 고객·관리자 화면
```

- seed는 같은 데이터로 다시 실행해도 중복 상품을 만들지 않는다.
- SKU와 슬러그를 안정적인 키로 사용한다.
- 운영 환경에서는 데모 seed가 자동 실행되지 않게 프로필을 분리한다.
- 관리자 비밀번호와 비회원 조회 코드 원문은 seed 파일에 넣지 않는다.
- 실제 공급처 상품으로 바꿀 때 내부 상품코드와 이미지 키의 매핑표를 남긴다.

## 6. 개인정보와 시연 안전

- 고객 이름은 `김데모`, `박테스트`처럼 가상임이 명확한 값만 사용한다.
- 이메일은 `example.com` 도메인을 사용한다.
- 전화번호·주소는 실제 연락이나 배송에 사용하지 않는 가상 값으로 표시한다.
- 실제 카드 결제, 문자, 이메일, 배송 요청을 발생시키지 않는다.
- 화면과 관리자에 테스트 결제·가상 주문임을 표시한다.

## 7. 제작 순서

1. API 계약과 상품 스키마를 먼저 확정한다.
2. 상품 4개짜리 최소 seed로 목록·상세·장바구니를 개발한다.
3. 화면 구조가 안정되면 24개 전체 상품 CSV/JSON을 만든다.
4. 대표 이미지와 기획전 이미지를 자체 제작해 저장소 키에 연결한다.
5. 8월 26일 전까지 상품 설명, 옵션, 품절, 가격, 대체 텍스트를 검수한다.
6. 실제 공급처 자료가 도착하면 별도 복사본에서 매핑 후 교체한다.

## 8. 완료 조건

- 24개 상품이 실제 PostgreSQL에서 조회된다.
- 옵션 있음·없음, 재고 있음·품절 상품이 섞여 있다.
- 홈 7개 섹션과 4개 기획전에 충분한 콘텐츠가 연결된다.
- 고객 화면과 관리자 화면에서 같은 상품 데이터가 보인다.
- 이미지 사용 근거를 설명할 수 있고 타사 자산을 복제하지 않았다.
- 모든 고객·주문 정보가 가상 데이터다.
