# 기능 QA 체크리스트

마지막 갱신: 2026-08-20

## 1. 목적과 사용법

이 문서는 로컬 MVP와 향후 EC2 배포본의 기능·보안·반응형·운영 품질을 같은 기준으로 확인하기 위한 실행 체크리스트다. 자동 테스트 결과만으로 대체하지 않고 실제 브라우저와 DB 상태를 함께 확인한다.

- 체크 전 환경을 `local-desktop`, `local-mobile-360`, `deployed-desktop`, `deployed-mobile` 중 하나로 기록한다.
- 통과는 `[x]`, 미실행은 `[ ]`, 현재 범위 밖은 `N/A`로 표시한다.
- 실패 시 화면 캡처, 요청·응답, 콘솔 오류, 서버 로그, 재현 절차를 결함 기록에 연결한다.
- 실제 비밀번호, 세션·CSRF 쿠키, 비회원 조회 토큰, 개인정보는 캡처나 Git에 남기지 않는다.

### 결함 우선순위

| 등급 | 의미 | 예시 |
|---|---|---|
| P0 | 보안 노출·데이터 손실·전체 서비스 중단 | 타인 주문 열람, DB 유실, 결제·재고 중복 반영 |
| P1 | 핵심 흐름 중단 | 로그인, 장바구니, 주문, 결제, 관리자 주문 처리 불가 |
| P2 | 우회 가능한 부분 기능 문제 | 특정 필터 실패, 일부 화면 상태 갱신 지연 |
| P3 | 문구·간격·장식 문제 | 오탈자, 작은 정렬 차이 |

## 4. 공개 홈·기획전·상품

### 홈 `/`

- [ ] 공지, 히어로, 기획전, 인기 상품, 신상품, 탐색, 공간 콘텐츠, 서비스 안내가 표시된다.
- [ ] 히어로가 5초 후 다음 항목으로 전환된다.
- [ ] 히어로에 마우스를 올리거나 내부 요소에 포커스하면 자동 전환이 멈춘다.
- [ ] 운영체제의 동작 줄이기 설정에서는 자동 전환과 과도한 모션이 비활성화된다.
- [ ] 이전·다음 버튼과 점 버튼으로 원하는 슬라이드로 이동한다.
- [ ] 슬라이드 제목·설명·이미지·연결 링크가 서로 일치한다.
- [ ] 이미지가 없거나 실패해도 대체 UI 때문에 레이아웃이 무너지지 않는다.
- [ ] 홈 링크를 눌렀을 때 상품·기획전·필터 URL로 올바르게 이동한다.

### 기획전 `/collections`, `/collections/[slug]`

- [ ] 공개 기획전 3개가 정해진 순서로 보인다.
- [ ] 상세 제목·설명·이미지와 연결 상품이 올바르다.
- [ ] 존재하지 않는 slug는 정상적인 404 화면을 표시한다.
- [ ] 기획전 상품에서 상세·찜·장바구니 흐름으로 이동할 수 있다.

### 상품 `/products`, `/products/[slug]`

- [ ] 목록 첫 진입, 페이지네이션, 정렬이 정상 작동한다.
- [ ] 검색어, 동물 종, 브랜드, 카테고리, 재고 필터가 각각 작동한다.
- [ ] 여러 필터를 함께 적용하고 새로고침해도 URL과 결과가 일치한다.
- [ ] 결과 없음, API 오류, 로딩 상태가 각각 구분된다.
- [ ] 상품 카드의 브랜드·이름·가격·할인가·품절 상태가 상세와 일치한다.
- [ ] 상세 이미지 갤러리와 대체 텍스트가 정상이다.
- [ ] 옵션을 바꾸면 가격·재고·최대 구매 수량이 즉시 갱신된다.
- [ ] 품절 옵션은 구매할 수 없고 수량 제한을 넘길 수 없다.
- [ ] 존재하지 않거나 비공개인 slug는 404를 표시한다.

## 5. 회원·세션·접근 제어

- [ ] 새 이메일로 회원가입하면 로그인 상태가 된다.
- [ ] 중복 이메일, 잘못된 이메일, 짧은 비밀번호, 필수값 누락이 필드 오류로 표시된다.
- [ ] 잘못된 휴대전화 번호는 일반 오류가 아니라 휴대전화 입력칸 아래의 구체적인 오류로 표시된다.
- [ ] 잘못된 비밀번호로 로그인할 수 없고 민감한 원인이 노출되지 않는다.
- [ ] 일반 회원 로그인 후 `/account`, `/mypage`, `/mypage/orders`에 접근할 수 있다.
- [ ] 로그아웃 후 회원 전용 페이지 접근 시 로그인으로 이동한다.
- [ ] `next`에 외부 URL, `//`, 역슬래시를 넣어도 외부 사이트로 이동하지 않는다.
- [ ] 일반 회원이 `/admin`과 `/api/v1/admin/**`에 접근할 수 없다.
- [ ] 관리자가 고객 주문 생성 기능을 사용할 수 없다.
- [ ] 새로고침 후 로그인 세션이 유지되고 로그아웃 후에는 재사용되지 않는다.
- [ ] 회원가입·로그인·로그아웃 등 상태 변경 요청에 CSRF 검사가 적용된다.

## 6. 찜·장바구니·방문자 병합

- [ ] 비로그인 상태에서 옵션 상품을 장바구니에 담을 수 있다.
- [ ] 같은 옵션을 다시 담으면 정책에 맞게 수량이 합쳐진다.
- [ ] 장바구니 수량 변경·삭제와 헤더 배지가 즉시 일치한다.
- [ ] 최대 구매 수량과 현재 재고를 넘길 수 없다.
- [ ] 비회원 상품 상세에는 찜 버튼 대신 로그인 안내가 보이고 익명 찜 API는 `401`이다.
- [ ] 고객 회원 로그인 후 찜 추가·조회·해제가 유지된다.
- [ ] 로그인하면 같은 옵션의 방문자·회원 장바구니 수량이 제한 안에서 병합된다.
- [ ] 방문자 장바구니가 있어도 신규 가입 회원은 빈 장바구니·빈 찜으로 시작하고, 로그아웃 뒤 이전 방문자 장바구니가 다시 나타나지 않는다.
- [ ] 병합 요청을 반복해도 수량이 중복 증가하지 않는다.
- [ ] 관리자 로그인은 방문자 장바구니를 소비하지 않고 찜 API는 `403`이다.
- [ ] 서로 다른 시크릿 창의 방문자 장바구니가 서로 섞이지 않는다.

## 7. 주문·시뮬레이션 결제

### 견적과 주문서

- [ ] 장바구니의 구매 가능한 항목이 주문서에 전달되고 품절·구매불가 항목은 제외된다.
- [ ] 구매자·수령자·전화·주소·필수 동의 검증이 작동한다.
- [ ] 상품 합계가 50,000원 미만이면 배송비 3,000원이 적용된다.
- [ ] 상품 합계가 50,000원 이상이면 배송비가 0원이다.
- [ ] 브라우저에서 표시 가격을 변조해도 서버가 DB 가격으로 다시 계산한다.
- [ ] 주문 직전 품절·가격 변경·장바구니 변경을 서버가 거부하거나 최신 값으로 안내한다.

### 회원 주문

- [ ] 회원 주문 생성 후 주문번호가 발급되고 선택 장바구니 항목만 제거된다.
- [ ] 같은 주문 멱등성 키를 재전송해도 주문이 하나만 생성된다.
- [ ] `APPROVE` 시 주문·결제·재고 예약이 한 번만 승인된다.
- [ ] 결제 승인 요청을 반복해도 재고가 중복 차감되지 않는다.
- [ ] `FAIL` 시 주문 실패와 재고 복원이 한 번만 반영된다.
- [ ] `FAIL` 처리된 주문 항목은 장바구니에 자동 복원되지 않으며 새 주문을 위해 상품을 다시 담아야 한다.
- [ ] 주문 완료 화면과 회원 주문 상세의 금액·상품·상태가 일치한다.

### 비회원 주문과 조회

- [ ] 비회원으로 주문을 생성하고 조회 토큰을 안전하게 안내받는다.
- [ ] 같은 주문 키·같은 요청의 재응답에서 같은 조회 토큰을 받는다.
- [ ] 주문번호만으로는 비회원 주문을 조회할 수 없다.
- [ ] 잘못된 조회 토큰으로는 주문을 조회할 수 없다.
- [ ] 잘못된 주문번호와 잘못된 토큰은 주문 존재 여부를 구분할 수 없는 일반적인 실패로 응답한다.
- [ ] 주문번호와 올바른 토큰으로만 주문 상세를 확인할 수 있다.
- [ ] 조회 토큰이 URL, 서버 로그, DB 원문에 남지 않는다.

### 만료·동시성·오류

- [ ] 20분 예약 만료 시 주문·결제가 취소되고 재고가 한 번 복원된다.
- [ ] 만료된 결제 키를 반복 호출해도 계속 만료 오류이며 승인되지 않는다.
- [ ] 같은 장바구니 행을 동시에 주문하면 한 요청만 성공한다.
- [ ] 백엔드 연결 실패 시 프론트가 성공 화면을 보여주지 않는다.
- [ ] 실제 카드 과금이 없는 `SIMULATED` 결제임이 화면에 명확하다.

## 8. 회원 주문 조회

- [ ] `/mypage/orders`에는 현재 회원의 주문만 보인다.
- [ ] 주문 목록과 상세의 주문·결제·배송 상태가 일치한다.
- [ ] 다른 회원 주문번호를 직접 입력해도 조회할 수 없다.
- [ ] 로그아웃 후 이전 회원 주문 상세를 다시 열 수 없다.
- [ ] 주문 당시 상품명·옵션·가격·주소 스냅샷이 이후 상품 수정의 영향을 받지 않는다.

## 9. 관리자

- [ ] `/admin/login`에서 관리자만 로그인할 수 있다.
- [ ] 대시보드의 상품·주문·재고 요약이 실제 데이터와 일치한다.
- [ ] 상품 검색·상태 필터·페이지 이동이 정상이다.
- [ ] 필수 상품 정보와 옵션을 입력해 새 상품을 등록할 수 있다.
- [ ] PC 파일 선택기와 모바일 사진 선택기에서 JPEG·PNG·WebP를 여러 장 선택하고 업로드 진행률·미리보기·개별 실패 재시도를 확인할 수 있다.
- [ ] 이미지 대체 텍스트와 앞뒤 순서를 바꿀 수 있고 첫 이미지가 고객 화면의 대표 이미지로 반영된다.
- [ ] 최대 8장, 장당 8MB, 가로·세로 10,000px·전체 4천만 픽셀 제한과 HEIC/HEIF·GIF·움직이는 WebP 거절이 한국어 오류로 표시된다.
- [ ] 업로드 중 상품 저장이 차단되고 `PUBLISHED` 선택 시 이미지가 없으면 저장되지 않는다.
- [ ] 익명·일반 회원 업로드는 `401`/`403`, CSRF 없는 관리자 업로드는 거절되며 실패 파일이 상품 JSON에 연결되지 않는다.
- [ ] 가격·재고·판매 상태 수정이 고객 상품 화면에 반영된다.
- [ ] 옵션의 오래된 `version`으로 저장하면 충돌을 알리고 덮어쓰지 않는다.
- [ ] 상품 수정 화면의 별도 위험 영역에 있는 삭제 버튼은 상품명과 되돌릴 수 없는 결과를 확인한 뒤에만 요청을 보낸다.
- [ ] `PUBLISHED` 상품 삭제는 `409 PRODUCT_MUST_BE_UNPUBLISHED`로 거절되고 숨김 또는 판매 종료 안내를 표시한다.
- [ ] 주문 이력 상품의 첫 삭제는 `409 PRODUCT_HAS_ORDER_HISTORY`이고, 주문 스냅샷 보존·현재 상품 연결 해제를 별도로 확인한 뒤 `confirmOrderHistory=true`로만 다시 요청한다.
- [ ] 추가 확인 삭제 후 기존 회원·비회원 주문 상세의 상품명·브랜드·SKU·옵션·가격·이미지와 결제 이력은 그대로이며 현재 상품·옵션 FK만 `NULL`이다.
- [ ] `ACTIVE` 재고 예약 상품은 추가 확인 뒤에도 `409 PRODUCT_HAS_ACTIVE_RESERVATION`으로 거절되고 예약 종료 전까지 삭제 버튼을 반복 실행하지 않게 안내한다.
- [ ] 홈 `PRODUCT` 직접 연결 상품은 `409 PRODUCT_IN_USE`로 거절되어 연결 해제를 안내한다.
- [ ] 오래된 상품 `version` 삭제는 `409 OPTIMISTIC_LOCK_CONFLICT`이며 익명·일반 회원·CSRF 없는 관리자 삭제는 권한 정책에 따라 거절된다.
- [ ] 삭제 가능한 상품을 삭제하면 상품·옵션·이미지 메타데이터·분류 연결·기획전 연결·해당 장바구니·찜 항목은 사라지고 다른 상품 데이터에는 영향이 없다.
- [ ] 삭제 성공은 `204`이고 목록으로 안전하게 돌아가며 `PRODUCT_DELETE` 감사 로그에는 삭제 대상과 종속 데이터 개수 요약이 남는다.
- [ ] 상품 삭제 후에도 업로드 이미지 실제 파일은 유지되며 화면은 이를 즉시 삭제했다고 표현하지 않는다.
- [ ] 주문 검색·필터·상세가 회원·비회원 주문을 올바르게 표시한다.
- [ ] 허용된 주문 상태 전이는 성공하고 금지된 역방향 전이는 거부된다.
- [ ] 관리자 상태 변경 감사 로그가 남는다.
- [ ] 홈 섹션과 히어로 수정이 공개 홈에 반영된다.
- [ ] 잘못된 홈 JSON과 오래된 version은 저장되지 않는다.
- [ ] 관리자 화면에서 실제 PG 환불이나 업로드 이미지 파일 물리 삭제·자동 고아 정리가 구현된 것처럼 표시하지 않는다.

## 10. 반응형·접근성·브라우저

- [ ] 360px에서 가로 스크롤 없이 홈·상품·장바구니·주문·관리자 핵심 화면을 사용할 수 있다.
- [ ] 데스크톱 1440px에서 콘텐츠 최대 폭과 간격이 지나치게 벌어지지 않는다.
- [ ] 확대 200%에서도 핵심 버튼과 입력 필드가 가려지지 않는다.
- [ ] Tab만으로 헤더, 슬라이드, 폼, 모달, 결제 흐름을 조작할 수 있다.
- [ ] 포커스 표시가 보이고 포커스 순서가 화면 순서와 일치한다.
- [ ] 모든 의미 있는 이미지에 적절한 대체 텍스트가 있다.
- [ ] 폼 오류가 색상만이 아니라 문구로도 전달된다.
- [ ] 로딩 상태에 중복 클릭 방지가 적용된다.
- [ ] Chrome과 최소 한 개의 다른 엔진에서 핵심 구매 흐름이 통과한다.
- [ ] Console에 uncaught exception, hydration 오류, 반복 경고가 없다.

## 11. 데이터·DB 일관성

- [ ] 주문 화면 합계와 DB 주문 합계가 일치한다.
- [ ] 승인·실패·만료 전후 옵션 재고 수량이 기대값과 일치한다.
- [ ] 주문·결제·상태 이력이 중복되거나 누락되지 않는다.
- [ ] 비밀번호는 BCrypt 해시이고 방문자·비회원 조회 토큰 원문이 DB에 없다.
- [ ] Flyway를 빈 DB에 적용해도 V1~V7과 seed가 성공하고, V6까지 적용된 기존 DB에 V7을 올려도 주문 스냅샷이 유지된다.
- [ ] 기존 V5 DB에서 V6로 순차 업그레이드해도 데이터가 유지된다.
- [ ] 애플리케이션 재시작 후 세션·주문·상품·미디어가 정책대로 유지된다.

## 12. 배포 환경 추가 QA

- [ ] 외부 HTTPS에서 프론트 → API → PostgreSQL 흐름이 성공한다.
- [ ] HTTP 요청은 HTTPS로 리다이렉트된다.
- [ ] 세션·방문자·CSRF 쿠키에 운영 환경의 `Secure`, `HttpOnly`, `SameSite` 정책이 적용된다.
- [ ] 운영 DB 5432, 백엔드 8080, 프론트 3000 포트가 인터넷에 직접 노출되지 않는다.
- [ ] CORS가 승인된 출처만 허용한다.
- [ ] `.env`, DB 비밀번호, 배포 토큰이 Git·이미지·로그에 포함되지 않는다.
- [ ] EC2 또는 컨테이너 재시작 후 DB 볼륨과 미디어가 유지된다.
- [ ] `MEDIA_HOST_PATH`가 checkout 밖의 전용 절대경로이고 `10001:10001` 소유이며, 업로드 파일이 backend 재생성 뒤에도 같은 `/media/**` URL로 조회된다.
- [ ] DB dump와 같은 시점의 미디어 압축본·체크섬을 EC2 밖에 복사하고 별도 임시 경로에서 열어 볼 수 있다.
- [ ] PostgreSQL 백업을 별도 임시 DB에 실제 복원했다.
- [ ] 직전 정상 이미지·Compose 설정으로 롤백할 수 있다.
- [ ] 로그에 비밀번호, 쿠키, 조회 토큰, 전체 주소가 남지 않는다.
- [ ] 모바일 외부 네트워크에서 로그인·주문 흐름이 통과한다.

## 17. 자동화 우선순위

1. Playwright로 비회원 구매·조회, 회원 구매, 관리자 주문 처리의 브라우저 E2E를 자동화한다.
2. GitHub Actions에서 백엔드 테스트와 프론트 typecheck·lint·test·build·E2E를 실행한다.
3. k6로 홈·상품 목록·로그인·장바구니·주문 견적의 응답 시간과 오류율 임계값을 기록한다. 실제 주문 생성 부하는 격리된 QA DB에서만 수행한다.
4. OWASP ZAP Baseline을 배포된 테스트 주소에 수동 또는 CI로 실행하고 알려진 경고를 기준 파일로 관리한다.
5. Spring Boot Actuator 지표를 Prometheus/Grafana로 수집해 k6 실행 중 처리량·오류율·JVM·DB 풀 상태를 함께 관찰한다.

Kafka는 QA 도구가 아니다. 주문 생성 후 알림·분석·배송 연동처럼 독립 소비자가 실제로 필요할 때 `transactional outbox → Kafka producer → 멱등 consumer → retry/DLQ`를 하나의 후속 기능으로 검증한다. 현재 단일 EC2 MVP의 QA를 위해 먼저 추가하지 않는다.
