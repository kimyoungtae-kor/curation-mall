# 펫 라이프스타일 큐레이션몰 MVP — 제품 범위

## 0. 문서 정보

| 항목 | 내용 |
|---|---|
| 기준일 | 2026-08-20 |
| MVP 완료 목표일 | 2026-08-29 |
| 문서 상태 | MVP 구현 체크포인트 v1.3 |
| 대상 | 기획, 디자인, 프론트엔드, 백엔드, 운영 |
| 목적 | 짧은 개발 기간 안에 시연 가능한 범위를 고정하고, 이후 팀 개발로 이어질 수 있는 제품 경계를 정의한다. |

이 문서는 MVP 범위의 기준 문서다. 개발 중 새 아이디어가 생기면 즉시 구현하지 않고 `Must / Should / Later` 중 하나로 분류한 뒤 반영 여부를 결정한다.

## 1. 제품 정의

강아지·고양이 용품을 시작으로 향후 희귀동물과 펫룸까지 확장하는 **모바일 우선 펫 라이프스타일 큐레이션 커머스**다.

단순히 카테고리별 상품을 나열하는 대신, 고객의 상황과 생활 공간을 기준으로 상품과 콘텐츠를 함께 제안한다.

- Vetreska: 스크롤 리듬, 히어로 및 상품 슬라이드, 시각적 캠페인 경험
- WOOOF: 멀티브랜드 구성과 상황·테마별 큐레이션
- Duit design LAB / MAU: 반려동물 용품을 집 안 인테리어의 일부로 보여주는 관점
- Tuft + Paw: 콘텐츠에서 상품 탐색과 구매로 이어지는 흐름

레퍼런스의 구조와 사용 흐름만 참고하며, 이미지·문구·상품명·색상 조합·브랜드 표현을 복제하지 않는다.

## 2. MVP 목표

1. 사업자에게 링크 하나로 고객 구매 경험과 관리자 운영 경험을 시연한다.
2. 회원과 비회원 모두 상품 탐색부터 테스트 결제 완료까지 진행할 수 있게 한다.
3. 운영자가 개발자 도움 없이 상품, 옵션·재고, 홈 노출, 주문 상태를 관리할 수 있게 한다.
4. 향후 희귀동물, 공급처, 앱, 펫룸 기능을 추가할 수 있도록 핵심 데이터를 확장 가능한 형태로 설계한다.

### 핵심 성공 지표

MVP 단계에서는 실제 매출보다 아래 시연 가능 여부를 우선한다.

- 모바일과 데스크톱에서 주요 화면이 깨지지 않는다.
- 회원 및 비회원 구매 흐름이 각각 끝까지 완료된다.
- 장바구니, 찜, 회원, 주문, 결제 결과가 DB에 저장된다.
- 관리자가 등록·수정한 상품과 홈 콘텐츠가 고객 화면에 반영된다.
- 테스트 결제 결과와 주문 상태를 관리자에서 확인할 수 있다.

## 3. 사용자와 권한

| 사용자 | 설명 | 주요 권한 |
|---|---|---|
| 방문자 | 로그인하지 않고 둘러보는 고객 | 상품·기획전 조회, 장바구니 |
| 비회원 구매자 | 계정을 만들지 않고 주문하는 고객 | 주문·결제, 주문번호 기반 주문 조회 |
| 회원 | 가입 및 로그인한 고객 | 찜, 장바구니, 주문, 주문 내역, 기본 회원 정보 조회 |
| 관리자 | 쇼핑몰 운영 담당자 | 상품·기획전·홈 노출·재고·주문 관리 |

관리자 계정은 일반 회원과 권한을 분리하고, 관리자 API는 화면 노출 여부와 관계없이 서버에서 권한을 다시 확인한다.

## 4. 우선순위별 범위

### 4.1 Must — 8월 29일 시연에 반드시 포함

#### 고객용

- 모바일 우선 반응형 공통 레이아웃
- 홈 화면의 7개 기본 섹션
- 상황·테마별 기획전 목록 및 상세
- 상품 목록, 상품 상세, 이미지 갤러리 또는 슬라이드
- 상품 옵션 선택, 판매가, 재고 상태 표시
- 장바구니 추가, 수량 변경, 삭제
- 로그인 회원의 찜 추가·해제, 찜 목록
- 이메일 기반 회원가입, 로그인, 로그아웃
- 기존 고객 로그인 완료 시 방문자 장바구니를 회원 데이터에 병합
- 신규 회원가입은 방문자 장바구니·과거 방문자 찜을 승계하지 않고 빈 회원 데이터로 시작
- 회원 마이페이지와 주문 내역
- 회원 주문서 작성 및 테스트 결제
- 비회원 주문서 작성 및 테스트 결제
- 주문 완료 화면
- 비회원 주문 조회
- 품절, 빈 목록, 잘못된 접근, API 오류에 대한 기본 상태 화면

#### 관리자용

- 관리자 로그인 및 권한 보호
- 상품 등록·조회·수정, 판매 상태 변경과 안전 조건을 충족한 상품 삭제
- 기존 브랜드, 카테고리, 동물 종 분류 연결
- 상품 옵션, 가격, 재고와 관리자 이미지 파일 업로드·미리보기·대체 텍스트·노출 순서 관리
- 홈 배너와 정해진 홈 섹션의 문구·이미지·연결 대상·노출 순서 관리
- 주문 목록·상세 조회
- 주문, 결제 상태 확인 및 허용된 주문 상태 변경
- 회원 목록과 기본 정보 조회 API

#### 시스템·데이터

- PostgreSQL에 회원, 방문자, 상품, 옵션, 재고, 찜, 장바구니, 주문, 결제, 기획전 데이터를 영속 저장
- 서버에서 최종 상품 가격, 할인, 배송비, 결제 예정 금액 재계산
- 주문 생성 시 구매자·수령인·주소와 상품명·옵션명·가격을 주문 스냅샷으로 보존
- 회원 주문과 비회원 주문을 하나의 주문 모델로 관리하되, 비회원 주문은 회원 ID 없이 조회용 식별 정보를 보유
- 상품 이미지는 교체 가능한 저장소 계층에 파일로 보관하고 DB에는 안정적인 `storage_key`와 대체 텍스트·노출 순서만 저장
- 개발·시연용 초기 데이터 제공
- 비밀키와 DB 접속 정보는 코드 저장소에 포함하지 않고 환경 변수로 분리

## 6. 홈 화면 7개 기본 섹션

홈은 반복되는 상품 슬라이더로 과도하게 길어지지 않도록 아래 7개 섹션을 기본 틀로 고정한다.

1. **공지 바 + 반응형 헤더**  
   배송·프로모션 안내, 로고, 탐색 메뉴, 검색, 찜, 장바구니, 로그인 진입점을 제공한다.

2. **히어로 슬라이드**  
   최대 3장의 캠페인 배너로 구성하고, 각 슬라이드는 기획전·상품·콘텐츠 중 하나로 연결한다.

3. **상황별 기획전**  
   최소 2개를 노출한다. 초기 예시는 `여름철 반려동물 음수량 늘리기`와 `안전한 차량 탑승을 위한 카시트 베스트 아이템`이다.

4. **인기상품·신상품 슬라이드**  
   상품 카드에서 이미지, 브랜드, 상품명, 가격, 품절 여부, 찜 동작을 제공한다.

5. **동물·카테고리·브랜드 탐색**  
   초기 강아지·고양이 탐색을 제공하되, 데이터 구조는 새로운 동물 종을 추가할 수 있어야 한다.

6. **공간 중심 라이프스타일 콘텐츠**  
   반려용품을 인테리어와 연결해 보여주며 관련 기획전이나 상품 상세로 이동시킨다.

7. **서비스 안내 + 푸터**  
   배송·교환·반품 요약, 고객지원, 이용약관, 개인정보처리방침, 사업자 정보 영역을 제공한다.

## 7. 핵심 도메인과 운영 원칙

### 7.1 상품과 분류

- `동물 종`, `브랜드`, `카테고리`는 상품에 문자열로 고정하지 않고 별도 데이터로 관리한다.
- 강아지와 고양이 외 동물 종을 관리자에서 추가할 수 있는 구조를 전제로 한다.
- 판매 단위와 재고는 상품이 아니라 옵션 조합을 기준으로 관리할 수 있어야 한다.
- 가격과 금액은 원 단위 정수로 저장한다.
- 핵심 주문·재고 데이터는 JSON에 몰아넣지 않고 관계형 컬럼과 테이블로 관리한다.
- 동물 종별로 달라지는 부가 속성은 이후 확장을 고려해 유연한 속성 모델을 검토하되 MVP 필수는 아니다.

### 7.2 회원과 방문자

- 이메일은 중복 가입을 허용하지 않는다.
- 비밀번호는 평문으로 저장하지 않고 안전한 단방향 해시를 사용한다.
- 비로그인 장바구니는 추측하기 어려운 방문자 식별 쿠키와 연결한다.
- 찜 추가·조회·해제는 `CUSTOMER` 회원에게만 허용하고, 비회원에게는 로그인 안내를 표시한다.
- 회원 탈퇴 정책은 MVP 이후 확정하되, 주문 기록이 임의로 삭제되지 않게 회원과 주문의 생명주기를 분리한다.

### 7.3 주문과 결제

- 회원 주문은 회원 ID를 연결하고, 비회원 주문은 회원 ID를 비워 둔다.
- 회원의 프로필이나 상품 정보가 바뀌어도 과거 주문 정보는 바뀌지 않아야 한다.
- 결제 승인 전후 상태를 구분하고 같은 요청이 반복돼도 중복 승인·중복 주문이 생기지 않게 한다.
- 클라이언트가 전달한 금액만 신뢰하지 않으며, 서버 계산 금액과 결제 승인 금액이 일치할 때만 결제 완료로 처리한다.
- 테스트 결제라는 사실을 고객·관리자 화면에서 명확히 표시한다.

### 7.4 관리자 운영

- 상품과 기획전은 삭제보다 `임시 저장 / 공개 / 숨김 / 판매 종료` 상태 변경을 우선한다.
- 현재 `PUBLISHED`인 상품은 즉시 삭제할 수 없다. 관리자는 먼저 `HIDDEN` 또는 `DISCONTINUED`로 바꿔 고객 구매를 막고 삭제 여부를 다시 확인한다.
- 주문 이력이 있는 상품은 첫 삭제 요청에서 즉시 지우지 않고 주문 스냅샷 보존 사실을 별도로 확인한다. 관리자가 추가 확인하면 현재 상품·옵션 FK만 분리하고 과거 주문명·SKU·가격·이미지 스냅샷은 유지한 채 삭제할 수 있다.
- 결제 대기 중인 활성 재고 예약이 있으면 추가 확인 후에도 삭제하지 않는다. 홈 섹션이 해당 상품을 `PRODUCT`로 직접 연결하면 먼저 연결을 해제해야 한다.
- 위 조건을 통과한 상품만 최신 `version`을 확인한 단일 트랜잭션에서 상품 종속 DB 데이터와 함께 물리 삭제한다. 업로드 이미지 파일 자체는 삭제하지 않고 이후 고아 파일 정리 대상에 포함한다.
- 주문 상태 변경은 정의된 순서와 허용된 전이만 가능하게 한다.
- 홈은 자유 편집기가 아니라 정해진 7개 섹션의 콘텐츠와 순서를 관리하는 방식으로 제한한다.
- 상품 이미지는 PC 파일 선택기와 모바일 사진 선택기에서 같은 업로드 API로 전송한다. 서버가 형식·용량·해상도를 검증하고 생성한 `storage_key`만 상품에 연결하며 원본 파일명과 클라이언트 MIME만 신뢰하지 않는다.

## 8. 품질 기준

- 최소 지원 화면 폭에서 가로 스크롤과 주요 버튼 겹침이 없어야 한다.
- 키보드로 로그인, 상품 옵션 선택, 장바구니, 주문 폼의 주요 동작을 수행할 수 있어야 한다.
- 입력 오류는 필드 근처에 이해할 수 있는 한국어로 표시한다.
- 로딩 중 중복 제출을 막고, 실패 시 재시도 또는 복귀 경로를 제공한다.
- 관리자 경로와 API는 미인증·미인가 접근을 차단한다.
- 회원 비밀번호, 세션, 결제키, 비회원 조회 정보가 로그나 URL에 불필요하게 노출되지 않게 한다.
- 주문·결제·재고의 핵심 업무 규칙은 백엔드 테스트로 검증한다.

## 9. 데모 완료 기준

아래 항목이 모두 재현되면 MVP 데모가 완료된 것으로 판단한다.

1. 배포 링크를 모바일과 데스크톱 브라우저에서 열 수 있다.
2. 홈의 7개 섹션과 3장 이하의 히어로 슬라이드가 정상 동작한다.
3. 기획전에서 상품 상세로 이동하고, 옵션을 선택해 장바구니와 찜에 담을 수 있다.
4. 새 회원을 가입시키고 로그인·로그아웃할 수 있다.
5. 회원이 테스트 결제를 완료하면 마이페이지 주문 내역과 관리자 주문 목록에 같은 주문이 보인다.
6. 비회원이 테스트 결제를 완료한 뒤 주문번호와 검증 정보로 주문을 조회할 수 있다.
7. 관리자가 새 상품 또는 기존 상품에 이미지를 업로드해 대표 순서를 정하고, 고객 화면에서 변경 사항을 확인할 수 있다.
8. 관리자가 홈 섹션과 히어로 콘텐츠를 바꾸고, 고객 홈에서 결과를 확인할 수 있다.
9. 관리자가 주문 상세와 테스트 결제 상태를 확인하고 허용된 주문 상태를 변경할 수 있다.
10. 품절 옵션은 구매할 수 없고, 결제 예정 금액은 서버의 상품 가격과 일치한다.
11. 새로고침 후에도 DB에 저장된 회원, 찜, 장바구니, 주문 데이터가 유지된다.
12. 데모 계정, 데모 상품, 정상 결제 시나리오와 실패 시 복구 경로가 준비돼 있다.

## 10. 범위 변경 규칙

- Must 변경은 일정, DB, API, 화면, 테스트에 미치는 영향을 함께 기록한 뒤 반영한다.
- 2026-08-14 이후 새로운 Must 추가는 기존 Must 하나를 제거하거나 완료일 조정이 합의된 경우에만 허용한다.
- 2026-08-23까지 고객 구매 흐름을 완료하고, 2026-08-26부터는 신규 기능을 추가하지 않는다.
- 배포 대상 서버는 별도 점검 후 결정하되, 배포 환경 차이로 인한 위험을 줄이기 위해 개발 중간에 빈 애플리케이션과 DB 연결을 한 번 검증한다.

## 11. 2026-08-20 구현 체크포인트

현재 코드에는 회원가입·로그인·로그아웃·현재 사용자 확인, 방문자 식별, 회원 전용 DB 찜, 회원·비회원 DB 장바구니와 기존 고객 로그인 시 장바구니 병합, 신규 가입 시 방문자 데이터 정리, 회원·비회원 주문, 서버 금액 재계산, 20분 재고 예약, 테스트 결제 성공·실패·멱등 처리, 회원·비회원 주문 조회가 구현돼 있다.

관리자 범위는 상품 등록·수정·판매 상태와 조건부 삭제, 옵션·재고, 이미지 파일 업로드와 메타데이터 연결, 주문 조회·허용 상태 전이, 회원 목록 API, 홈 7개 섹션과 히어로 편집까지 구현한다. 상품 삭제는 공개 중·활성 예약·홈 직접 연결·오래된 `version`을 서버에서 다시 검사한다. 주문 이력이 있으면 별도 확인을 한 번 더 받은 뒤 주문·결제·상품 스냅샷의 현재 카탈로그 FK를 분리하고, 삭제 가능한 상품만 종속 DB 데이터와 함께 트랜잭션으로 제거한다. 공개 기획전은 seed와 공개 조회 화면으로 제공한다. 기획전 CRUD, 분류 CRUD, 회원 상세는 이번 구현에 포함하지 않고 `Later`로 유지한다. 파일 업로드는 기존 상품 CRUD의 수동 `storageKey` 입력을 대체하는 범위 변경이며, 업로드 파일 물리 삭제와 자동 고아 정리는 포함하지 않는다.

local/test 시연 데이터는 가상 상품 24개, 옵션 26개, 브랜드 4개, 카테고리 8개, 기획전 3개, 품절 상품과 회원·비회원 주문 예시로 구성한다. 신규 상품 다수는 기존 자체 제작 데모 이미지 4종을 재사용하므로 실제 상품 자료가 확정되면 교체해야 한다.
